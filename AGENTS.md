# AGENTS.md

## Repo shape
- uv workspace (`pyproject.toml`, `uv.lock`): Python 3.12 packages in `model/` (`zonos3`), `servers/sgl/` (`zonos3_sgl`, Linux/NVIDIA), `servers/mlx/` (`zonos3_mlx`, Apple Silicon), `tools/` (`zonos3-tools`, no package build), `servers/api/` (`zonos3-api`, conformance/spec checks). Shared runtime/model code lives in `model/src/zonos3`; servers implement the same HTTP contract in `servers/api/openapi.yaml`.
- pnpm workspace (`pnpm-workspace.yaml`, root `pnpm-lock.yaml`): `studio/`, `studio/mcp/`, `servers/web/`. `studio/dist/` is committed and served from checkouts without Node (`.gitignore` exception) — rebuilding studio changes tracked output.
- Non-uv/native pieces: `servers/ggml/` (C++/ggml server + CLI; CMake build, links `third_party/zyphra-textnorm`), `servers/space/` (HF Space), `assets/` (runtime assets), `docs/` (API/guide/architecture). `servers/api/openapi.yaml` and bundled `openapi.json` are the cross-server API source of truth.

## Setup and environment
- Clone/init submodules as needed: `git submodule update --init third_party/fusealign-multilingual` (FuseAlign, used by Python workers/edit flows), `servers/ggml/ggml`, and `third_party/zyphra-textnorm` (needed for ggml/text-normalizer native builds).
- Python deps: `uv sync --locked --all-packages` (Linux/NVIDIA), `uv sync --locked --package zonos3-mlx` (Apple Silicon). `uv` uses workspace sources/overrides from root `pyproject.toml` (notably `apache-tvm-ffi==0.1.8.post2`, local `fusealign-hub`).
- Optional `phonemize` dep group is GPL-3.0/opt-in (`uv sync --locked --group phonemize` or package-specific `--group phonemize`); sgl/mlx serve scripts run with it when applicable.
- For CUDA/sgl work, source the environment first: `source servers/sgl/scripts/env.sh` (sets CUDA/toolchain/kernel env; chooses portable Triton/GDN kernels on pre-Hopper GPUs). Many sgl commands/tests assume this env.
- JS deps: `pnpm install` at repo root.

## Common commands
- SGL dev/tests (CUDA env): `source servers/sgl/scripts/env.sh && uv run --locked --group phonemize pytest` (root pytest config runs `model/tests`, `servers/sgl/tests`, `servers/mlx/tests`, `tools/tests`, `servers/api/tests/test_spec.py` with coverage for `zonos3`, `zonos3_sgl`, `zonos3_mlx`).
- GPU/model tests are marked `gpu` and only meaningful when `ZONOS3_TEST_MODEL` points to a checkpoint and a GPU is available; do not expect them to run in CPU-only environments.
- API conformance (against any live server implementing the spec): `uv run --package zonos3-api pytest servers/api/tests/conformance --base-url http://127.0.0.1:1919` (tests for unsupported capabilities skip).
- MLX (Apple Silicon): `uv run --package zonos3-mlx pytest servers/mlx/tests` (skips elsewhere).
- GGML parity (after building ggml): `uv run --package zonos3-tools pytest servers/ggml/tests/parity --ggml-build servers/ggml/build`. GGML build: `cd servers/ggml && cmake -B build -DCMAKE_BUILD_TYPE=Release && cmake --build build -j` (CUDA: `-DGGML_CUDA=ON` to e.g. `build-cuda`).
- Studio/web: `pnpm --dir studio typecheck|build|test|dev` (scripts run `gen:api` from `servers/api/openapi.json` to `studio/src/api/schema.ts`). `pnpm --dir servers/web test|typecheck|build`, `pnpm --dir studio/mcp test`, `pnpm --dir servers/web parity` (WebGPU/headless Chrome) as documented in package scripts/READMEs.

## Conventions and gotchas
- Generated client types: `studio/src/api/schema.ts` and `servers/web/src/api/schema.ts` are regenerated by `pnpm ... gen:api` from `servers/api/openapi.json`; treat them as generated artifacts and keep API/schema changes consistent across spec, servers, and generated consumers.
- Ruff is configured in root `pyproject.toml` (line-length 120, `py312`, lint `W,F,I,C4`; excludes `model/src/zonos3/models/third_party`, `third_party`, ggml/vendor dirs, `.avsync`). Pre-commit (`.pre-commit-config.yaml`) runs standard hooks plus `ruff-check --fix`, `ruff-format`, and `clang-format` for C++/CUDA (excludes `servers/ggml/vendor/`, `studio/dist/`, and `servers/sgl/src/zonos3_sgl/kernel/csrc/include/zonos3/nccl227.h`).
- Prefer executable/config sources over prose when they disagree: workspace/package manifests, `servers/*/scripts/*`, `servers/api/openapi.yaml`, and package test/script definitions. This repo has no `.github/workflows` CI checked in.
- Avoid editing vendored/submodule/large generated areas unless the task requires it (`third_party/`, `servers/ggml/ggml`, `servers/ggml/vendor/`, `studio/dist/`).
